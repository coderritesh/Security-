
# Day 2 — Windows Authentication & Event Logs: Interview Questions

## 1. What is Windows Event Viewer?

Windows Event Viewer is a built-in Windows tool used to view and investigate logs generated by the operating system, applications, and security components.

A SOC Analyst uses it to investigate failed logins, successful logins, account changes, and other security-related activities.

## 2. How do you open Event Viewer?

Press `Win + R`, type `eventvwr`, and press Enter.

Alternatively, search for **Event Viewer** in the Windows Start menu.

## 3. What are the main types of Windows logs?

* **Application:** Events generated by applications.
* **Security:** Authentication, account management, and security audit events.
* **System:** Events related to Windows services, drivers, and system components.
* **Setup:** Windows installation and configuration events.
* **Forwarded Events:** Events received from other computers when event forwarding is configured.

## 4. Which Windows log is important for authentication investigation?

The **Security log** is particularly important because it contains security audit events such as successful logons, failed logons, and account management activities, depending on the audit configuration.

Path in Event Viewer:

`Windows Logs → Security`

## 5. What is Event ID 4624?

Event ID **4624** indicates that an account was successfully logged on.

A SOC Analyst investigates the account, timestamp, logon type, source information where available, and related activity to determine whether the login was legitimate.

## 6. What is Event ID 4625?

Event ID **4625** indicates that an account failed to log on.

Possible reasons include an incorrect password, an incorrect username, or other authentication failures.

A single 4625 event does not automatically indicate an attack.

## 7. What is the difference between Event ID 4624 and 4625?

| Event ID | Meaning          |
| -------- | ---------------- |
| 4624     | Successful logon |
| 4625     | Failed logon     |

A SOC Analyst uses these events to understand authentication activity and identify potentially suspicious patterns.

## 8. What is a brute-force attack?

A brute-force attack is an attempt to gain access by trying many possible passwords or credentials.

In Windows logs, repeated Event ID 4625 entries may indicate possible brute-force activity.

However, the analyst must investigate the frequency, target account, source, logon type, and whether a successful login followed the failures.

## 9. How would you investigate multiple failed logins followed by a successful login?

I would investigate the following:

1. Identify the affected user account.
2. Check the timestamps and frequency of failed logons.
3. Examine the source IP address and workstation information, if available.
4. Review the logon type.
5. Check whether a successful Event ID 4624 followed the failures.
6. Investigate subsequent activity, including suspicious processes or account changes.
7. Correlate related events before deciding whether the activity is suspicious.

Multiple failed logons followed by a successful login are a warning sign, not automatic proof of an attack.

## 10. What is a Windows Logon Type?

A Logon Type describes the kind of logon associated with an authentication event.

Common examples include:

| Logon Type | Meaning                                             |
| ---------- | --------------------------------------------------- |
| 2          | Interactive logon, such as a local console sign-in  |
| 3          | Network logon, such as accessing a network resource |
| 4          | Batch logon                                         |
| 5          | Service logon                                       |
| 7          | Workstation unlock                                  |
| 10         | RemoteInteractive logon, commonly Remote Desktop    |
| 11         | CachedInteractive logon                             |

The meaning of an event should be interpreted alongside the account, source, and surrounding activity.

## 11. Where are Windows Event Log files stored?

Windows event log files are commonly stored at:

`C:\Windows\System32\winevt\Logs\`

Examples include:

* `Security.evtx`
* `System.evtx`
* `Application.evtx`

A SOC Analyst can examine the logs through Event Viewer or approved log collection tools.

## 12. What information should you check in Event ID 4625?

Important fields include:

* Account Name
* Failure Reason
* Logon Type
* Status and Sub Status
* Workstation Name
* Source Network Address, if available
* Process Information

These details help determine why the authentication failed and where the request may have originated.

## 13. What do Status and Sub Status mean in Event ID 4625?

Status and Sub Status provide codes that help explain an authentication failure.

For example:

* `0xC000006D` — Generic logon failure.
* `0xC000006A` — Incorrect password for the specified account.

The exact interpretation should be checked against the event details and the relevant Windows documentation.

## 14. What is the difference between an event and an attack?

An **event** is a recorded activity. An **attack** is malicious activity intended to compromise a system or account.

For example, a failed login is an event. Repeated failed logins from an unusual source, followed by a successful login and suspicious activity, may indicate an attack.

A SOC Analyst needs evidence and context before making a conclusion.

## 15. What questions should a SOC Analyst ask during an investigation?

A useful investigation framework is:

* **Who?** Which account or user was involved?
* **When?** When did the activity occur?
* **What?** What event happened?
* **Where from?** What source IP or workstation was involved?
* **How?** What logon type or process was associated with the event?
* **What next?** What activity occurred afterward?

## 16. What practical did you perform on Day 2?

I performed a controlled Windows authentication test using Event Viewer.

First, I intentionally entered an incorrect password and observed Event ID 4625. Then I entered the correct password and observed Event ID 4624.

I reviewed the event details and learned how to correlate authentication events during a basic SOC investigation.

## 17. What did you learn from this practical?

I learned how to locate Windows Security Logs, identify failed and successful logons, inspect authentication details, and build a basic timeline.

Most importantly, I learned that a single event should not be treated as proof of an attack. A SOC Analyst must correlate events and investigate the surrounding context.

## Key Revision

* **4624** → Successful Logon
* **4625** → Failed Logon
* **Logon Type 2** → Interactive
* **Logon Type 3** → Network
* **Logon Type 10** → RemoteInteractive / commonly RDP
* **Security Log** → Important source for authentication investigation
* **SOC methodology** → Event → Pattern → Correlation → Investigation → Conclusion

## Interview Tip

When answering a scenario-based question, explain **what you would check, why you would check it, and what evidence would support your conclusion**. Avoid declaring an attack based on one Event ID alone.
